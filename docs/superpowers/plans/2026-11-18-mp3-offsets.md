# MP3 Positions in Serato and rekordbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MP3 cues, loops and grids land in the same place in Open Jockey, Serato and rekordbox, both on export and when a guest stick is read.

**Architecture:** `decode::LeadIn` learns three facts from the MP3's first frame:
- whether it has a Xing/Info frame;
- which encoder wrote it;
- how many samples are in one frame.

One function, `interop::export::timing::app_offset_seconds`, turns those facts into each app's offset from Open Jockey's timeline. `app_seconds` (export) and a new inverse, `ours_seconds` (guest readers), both use it. The OJCAL stick, cut down, becomes the fixture every value is pinned against.

**Tech Stack:** Rust workspace; crates `decode` (symphonia) and `interop`.

**Spec:** `docs/superpowers/specs/2026-11-18-mp3-offsets-design.md`

## Global Constraints

## Review Focus

1. **Odd bytes before the first frame.** An MP3 with an ID3v2 tag that uses padding or a footer, an APE tag, or junk before the first frame sync must still find the real first frame. A false sync inside the ID3 tag must never be taken as a frame. Test: Task 1's `junk_and_padding_before_the_first_frame`.
2. **A short header.** A truncated file, or a Xing/Info frame cut off before the encoder string, gives `info_encoder: None`. It never panics or reads out of bounds. Test: Task 1's `a_cut_info_frame_reads_no_encoder`.
3. **A VBRI header (Fraunhofer) or an unknown encoder string.** VBRI isn't measured, so it counts as no Xing/Info frame: no shift, the same as today for rekordbox. An unknown encoder in a Xing/Info frame is treated as LAME-style (spec "my call"). Test: Task 2's `unmeasured_headers_follow_the_spec_defaults`.
4. **A re-export to a stick written before this change.** MP3 positions are rewritten in the Serato tags, the Serato database and `rekordbox.xml`, and VirtualDJ files stay byte-identical. Test: Task 4's `a_re_export_moves_only_mp3_serato_and_rekordbox_positions`.
5. **A guest track whose header can't be read** (an unreadable or vanished file while the stick is being read). It gets no shift, never a crash, and its other cues stay. Test: Task 3's `an_unreadable_mp3_header_gets_no_shift`.

### Task 2: One offset function

**Files:**
- Modify: `crates/interop/src/export/timing.rs`.
- Test: `crates/interop/src/export/timing.rs` (unit tests) and `crates/interop/tests/ojcal.rs`.

**Interfaces:**
- Consumes: `decode::LeadIn` and `InfoEncoder`, from Task 1.
- Produces:
  ```rust
  /// App position − Open Jockey position, in seconds, for one file.
  pub fn app_offset_seconds(app: App, kind: FileKind, lead_in: &LeadIn, sample_rate: u32) -> f64;
  /// Open Jockey frames → the app's seconds (export). Unchanged signature.
  pub fn app_seconds(app: App, frames: f64, t: &ExportTrack) -> f64;
  /// The app's seconds → Open Jockey seconds (guest readers).
  pub fn ours_seconds(app: App, app_seconds: f64, kind: FileKind, lead_in: &LeadIn, sample_rate: u32) -> f64;
  ```
  `SERATO_INFO_FRAME_FRAMES` is removed.
- Rules, from the spec, for `kind == Mp3 && info_frame`. Every other case is 0.
  - **Serato:**
    - 0.050 s when `frame_samples == 1152`.
    - 0.050 + 576/rate when it is 576.
  - **rekordbox:**
    - The base is `delay_frames` / rate, plus `frame_samples` / rate unless `info_encoder == Some(Lavc)`.
    - `info_encoder` None or Other counts as LAME-style.
    - These rekordbox values are relative to Open Jockey's timeline, which already trimmed `delay_frames`. So the offset is `(delay_frames + extra) / rate`, where `extra` is 0 for Lavc and `frame_samples` otherwise.
  - **VirtualDJ:** 0.
  - Document every rule in the code with its measured spec row.

    - Serato 22.05k → 0.050 + 576/22050;
    - rekordbox LAME 44.1k → (1105 + 1152)/44100;
    - rekordbox Lavc → 1105/44100;
    - rekordbox 48k LAME → (1105 + 1152)/48000;
